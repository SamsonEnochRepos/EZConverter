# Format matrix

Generated by `scripts/build_format_matrix.py` from the conformance run. **Only conversions that passed the
real-engine conformance suite are listed.** Multi-step routes (for example DOCX → PNG via PDF) are computed by the
planner from the composable steps below and are not listed here; query `/v1/targets` or `/v1/files/{id}/targets`.

Fidelity: `B` byte-preserving · `L` lossless re-encode · `~` lossy · `P` layout-altering · `S` semantic transformation

## Deliberately not supported

| Conversion | Why |
|---|---|
| Raster image → SVG | Needs vector tracing; it would only approximate the original. |
| PDF → DOCX/PPTX/XLSX/ODT… | Layout reconstruction is unreliable. PDF → TXT (text layer) and PDF → PNG/JPEG/TIFF (one page) are offered. |
| Scanned PDF/image → text | OCR is not implemented. |
| HEIC/HEIF images | Recognised, not decoded (no licensed decoder bundled). |
| Video → image frames, audio → image | Not implemented yet. |
| Password-protected PDF/ZIP/7z | Rejected with an explanation; passwords are never accepted. |

## Known limitations of verified conversions

- All formatting is removed; only text is kept.  
  _Applies to_: md→txt
- CSV has no types: numbers, booleans and null become text; null becomes an empty cell.  
  _Applies to_: json→csv
- Comments and key formatting from the source are not preserved (JSON has none).  
  _Applies to_: json→yaml
- Features unsupported by the target format may be altered or dropped; layout can shift slightly.  
  _Applies to_: csv→ods, csv→xls, csv→xlsx, docx→doc, docx→html, docx→odt, docx→rtf, doc→docx, doc→html, doc→odt, doc→rtf, html→doc … (+28 more)
- File contents and names are preserved. Ownership, permissions, links and special files are not.  
  _Applies to_: 7z→tar, 7z→tgz, 7z→zip, tar→7z, tar→tgz, tar→zip, tgz→7z, tgz→tar, tgz→zip, zip→7z, zip→tar, zip→tgz
- Formatting, images and styles are discarded; only text content is kept.  
  _Applies to_: docx→txt, doc→txt, html→txt, ods→csv, odt→txt, rtf→txt, xlsx→csv, xls→csv
- Generic mapping: attributes become '@name', text '#text', repeated siblings arrays. Ordering of differently named siblings and mixed content are not preserved.  
  _Applies to_: xml→json
- Images and raw content are not carried over (disabled for safety).  
  _Applies to_: docx→md, html→md, odt→md, rtf→md, txt→md
- Markdown has no page layout: styles are mapped to the target's defaults.  
  _Applies to_: md→docx, md→html, md→odt, md→rtf
- Only embedded text is extracted (no OCR); layout, images and reading order may not be preserved.  
  _Applies to_: pdf→txt
- Only the first sheet is exported.  
  _Applies to_: ods→csv, xlsx→csv, xls→csv
- Only the selected page is rendered; text becomes pixels.  
  _Applies to_: pdf→jpeg, pdf→png, pdf→tiff
- Pagination and fonts depend on the fonts installed on the converting machine.  
  _Applies to_: csv→pdf, docx→pdf, doc→pdf, html→pdf, odp→pdf, ods→pdf, odt→pdf, pptx→pdf, ppt→pdf, rtf→pdf, svg→pdf, txt→pdf … (+2 more)
- Styling, images and complex tables are simplified; only the document structure and text are kept.  
  _Applies to_: docx→md, html→md, odt→md, rtf→md, txt→md
- Uses the EZConverter typed-XML dialect so the result converts back to identical JSON.  
  _Applies to_: json→xml
- Vector content is rasterised at a fixed size.  
  _Applies to_: svg→png
- YAML-only features (comments, anchors, custom tags) are resolved or dropped.  
  _Applies to_: yaml→json
